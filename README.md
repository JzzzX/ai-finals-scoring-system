为 **2026 乖宝 AI 先锋赛决赛**设计的现场评分网站，围绕 12 支参赛队伍，完成评委打分、评分进度追踪、实时排名和成绩交付。评委端优先突出当前队伍与打分操作，管理员端负责名单、赛事状态和结果管理。

当前版本部署在 **个人购买的阿里云北京服务器**，由 **Zeabur 托管**，使用 **预备案子域名** `gambol-ai-finals-0928.preview.aliyun-zeabur.cn`，支持桌面与手机访问。**GitHub 与 Gitea 的主分支同步维护本外部评审版本**（评委姓名选择、管理员账密登录）。Gitea 本次同步仅更新仓库代码和文档，不代表公司内网服务已部署更新；具体赛事状态和评分进度以线上网站为准。

## 功能一览

| 使用场景 | 已实现功能 |
| --- | --- |
| 评委进入 | 首页选择本人姓名，确认身份后进入评分；显示姓名与职务 |
| 了解队伍 | 查看项目名称、成员、部门与团队合照；筛选全部、待评分和已评分队伍 |
| 提交评分 | 0—10 分综合评分，支持滑块、直接输入及 0.5 分微调；可填写评语 |
| 继续评分 | 本机草稿保存、提交成功后进入下一队、开放期间修改本人评分、冲突提示 |
| 管理赛事 | 管理员独立账密登录，维护成员与权限，开始、结束或重新开放评分 |
| 查看排名 | 每 2 秒同步，按一等奖 1 席、二等奖 3 席、三等奖 8 席分区展示名次和收齐进度，支持全屏 |
| 交付结果 | 导出 PNG 榜单图片、队伍汇总 CSV、逐评委明细 CSV |
| 保存数据 | SQLite 持久化、评分与操作留痕、一致性在线备份与停服恢复 |

界面采用暖白、墨绿与香槟金配色，融入乖宝吉祥物和奖杯。当前队伍以加深底色标识，评分区使用暖棕色，提交栏使用姜黄色；评委端与管理端共享字体与视觉规范。页面动效支持暂停，并遵循系统的“减少动态效果”设置。

## 登录与权限

**评委：** 打开首页，选择自己的姓名并确认。普通评委由管理员添加姓名与职务，无需自行注册或输入密码。

**管理员：** 从首页底部“管理员入口”或 `/admin/login` 进入，使用管理员账号和密码。首次部署不创建默认管理员，也不提供通用密码。

姓名选择是一种面向现场评审的便捷入口，**不验证选择者是否为本人**。名单公开可见，请仅选择自己的姓名。该入口签发的会话仅有评委权限，即使所选成员同时具备管理员角色，也不能由此进入后台。管理员权限需通过账密登录获取。

管理员可以查看结果、缺评进度及改分记录，不能替评委打分或修改他人的分数。停用成员会撤销其会话，但不会删除已提交成绩。当前云端使用 `AUTH_MODE=local`，不显示飞书登录入口。

## 评分与排名规则

| 规则 | 口径 |
| --- | --- |
| 分值 | 每队一个综合分，范围 0—10 分，步长 0.5 分；0 分有效 |
| 参考维度 | 六项维度供综合判断，系统不对六项分别打分或再次加权 |
| 平均分 | 所有已提交的有效评分等权求平均，不去最高分、最低分；缺评不按 0 分计入 |
| 显示精度 | 均分显示两位小数，排名使用未舍入结果 |
| 同分 | 完全同分并列，采用 1、1、3 的名次规则 |
| 奖项名额 | 一等奖 1 席（第 1 名）、二等奖 3 席（第 2—4 名）、三等奖 8 席（第 5—12 名） |
| 跨奖项同分 | 同分组横跨奖项边界时整体列入“奖项待确认”，不按出场顺序拆分；评分期间奖项均为暂定 |
| 未评分队伍 | 不产生名次，明确显示未排名 |
| 暂定与最终 | 评分未收齐，或赛事仍开放时，均为暂定排名；全部收齐且结束评分后才显示最终成绩 |

首次开始评分时固定本场评委名单，之后新增账号不会自动加入本场；重新开放评分也不改变名单。停用账号或移除评委角色不会抹去原有评分和缺评记录。

## 比赛当天怎么用

1. **准备名单。** 管理员核对评委姓名、职务、角色及 12 支队伍资料。管理员本人需要评分时，另行授予评委角色。
2. **开始评分。** 在“赛事设置”开始比赛，固定本场名单；提醒评委只选择本人姓名。
3. **评委打分。** 输入综合分与可选评语，点击提交。只有服务器确认成功后才计为已提交；本机草稿不等于已提交成绩。
4. **跟进进度。** 在“成绩与进度”查看缺评；需要投屏时打开“实时榜单”并进入全屏。网络异常时显示同步中断并保留上次数据。
5. **结束与交付。** 确认进度后结束评分，导出榜单图片及 CSV，另做数据库备份。缺评时即使结束评分，结果仍标记为暂定；重新开放须填写原因。

草稿按评委和队伍保存在当前浏览器。断网时可继续填写，恢复联网后需主动提交；草稿不跨设备同步。多人共用设备时，应退出当前评委身份再切换。

### 结果导出

- **PNG 榜单图片：** 在“实时榜单”点击“导出榜单图片”。图片按 1+3+8 奖项分区，包含完整排名、均分、已评人数、暂定或最终状态以及数据时间，可直接转发给评委和负责人。导出取点击时的数据快照，图片不会随后续评分自动变化。
- **队伍汇总 CSV：** 按名次排序，包含均分、已评与应评人数、收齐状态、成绩状态及导出时间。
- **逐评委明细 CSV：** 保留每位评委的评分、评语与更新时间，便于复核。

## 本地运行

需要 **Node.js 24 或更新版本、npm**。数据库初次初始化会导入队伍资料，但不会创建评委、默认密码或示例分数。

```sh
npm ci
cp .env.example .env
```

先将 `.env` 中的 `APP_ORIGIN` 改为本次实际访问地址。以本地生产式预览为例：

```dotenv
HOST=127.0.0.1
PORT=3001
APP_ORIGIN=http://127.0.0.1:3001
DB_PATH=./data/finals.sqlite
COOKIE_SECURE=false
AUTH_MODE=local
```

然后初始化管理员并启动：

```sh
npm run admin:create
npm run build
npm start
```

访问 <http://127.0.0.1:3001>。初始化命令会提示输入自选账号、姓名及至少 12 位密码，密码不回显；数据库已有账号时会拒绝重复初始化，后续成员通过后台管理。

开发时运行：

```sh
APP_ORIGIN=http://127.0.0.1:5173 npm run dev
```

访问 <http://127.0.0.1:5173>，Vite 将 `/api` 转发至后端 3001。访问地址应与 `APP_ORIGIN` 一致；生产式预览修改前端后需重新构建，修改后端后还需重启服务。

## 部署与数据维护

当前线上入口：**[gambol-ai-finals-0928.preview.aliyun-zeabur.cn](https://gambol-ai-finals-0928.preview.aliyun-zeabur.cn/)**。

根目录 `Dockerfile` 构建前后端，Zeabur 以单实例运行服务，并将 `/data` 挂载为持久化卷，数据库位于 `/data/finals.sqlite`。HTTPS、`APP_ORIGIN`、安全 Cookie 与持久化卷配置见 [Zeabur 部署说明](docs/zeabur-deployment.md)。当前使用代码包部署，**推送 GitHub 不会自动发布到云端**。

在线一致性备份：

```sh
npm run db:backup -- ./data/backups/before-finals.sqlite
```

备份目标必须尚不存在。服务运行时应使用该命令，不应只复制 SQLite 主文件而遗漏 WAL。

恢复前先停止服务和其他数据库写入进程：

```sh
npm run db:restore -- ./data/backups/before-finals.sqlite
npm start
```

恢复命令检查数据库完整性和结构版本，保存当前库恢复点，再执行替换；恢复后清除登录会话，需重新登录。检测到服务仍运行时会拒绝恢复。

SQLite 适用于本项目的单实例部署。账号、会话、评分和审计信息保存在数据库中；不要将 `.env`、数据库、备份或密码清单提交至 Git。多副本或共享网络盘部署需先调整数据方案。

## 技术与代码结构

前端使用 React、TypeScript、Vite；后端使用 NestJS；数据层使用 SQLite / better-sqlite3。评分写入采用事务、幂等请求和版本检查，处理重复提交及多设备改分冲突。

| 路径 | 职责 |
| --- | --- |
| `client/src/Entry.tsx` | 评委姓名选择、身份确认与管理员登录 |
| `client/src/Judge.tsx` | 队伍浏览、评分输入、草稿与提交 |
| `client/src/Admin.tsx` | 成绩、成员权限和赛事管理 |
| `client/src/Leaderboard.tsx` | 实时榜单与全屏展示 |
| `client/src/leaderboard-model.ts` | 榜单排序、并列与结果状态 |
| `client/src/leaderboard-export.ts` | PNG 榜单图片生成 |
| `client/src/*.css` | 入口、评分、管理、榜单与统一字体样式 |
| `client/public/` | 品牌素材、网站图标及团队照片 |
| `server/app.ts` | API、会话守卫、CSRF 与静态资源服务 |
| `server/service.ts` | 权限、固定名单、计分、审计与 CSV 导出 |
| `server/database.ts` | 数据结构、初始化与 SQLite 配置 |
| `shared/` | 共享类型、队伍资料及评分参考 |
| `scripts/` | 管理员初始化、备份与恢复 |
| `tests/` | 评分、权限、持久化、并发提交和排名边界测试 |
