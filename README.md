# AI先锋赛决赛评分系统

本地可运行的完整评分网站。React + Vite + TypeScript、NestJS、SQLite。正式库首次启动没有账号和历史分数；12 支队伍、44 条成员记录及 12 张团队照片已初始化。

## 当前状态

网站使用正式数据流程：12 支真实参赛队伍、初始无评分、赛事等待开始。不会自动创建评委，也不预填任何成绩。

**版本分开维护：GitHub 为外部评委账密版，Gitea 为公司内部飞书版。不要将本分支推送或镜像同步到 Gitea。**

当前版本统一使用管理员预先开通的账号密码，评委和管理员按角色访问；页面不提供飞书入口，`AUTH_MODE=local` 时飞书相关 API 返回 404。不开放自行注册，不创建通用评委或默认密码。每位评委单独分配账号，管理员通过“成员与权限”创建、停用账号或重置密码。

本次公网部署从新库开始，不迁入内部版历史评分。12 支队伍和赛事规则保留，评委名单稍后配置。云端设置与验收见 [Zeabur 部署说明](docs/zeabur-deployment.md)。旧的飞书接入文档仅供内部版本参考。

## 本地启动

环境：Node.js 24 或更新版本（本机验证 Node 26.6.0）、npm。在项目根目录执行：

```sh
npm ci
cp .env.example .env
npm run admin:create
npm run build
npm start
```

按提示输入自选账号、姓名和至少 12 位的独立密码，密码不回显；程序不会自动创建默认账号。首个管理员不自带评委角色。管理员已存在时初始化命令会拒绝再次创建，其他账号通过“成员与权限”添加。

浏览器访问 <http://127.0.0.1:3001>。如 3001 已有本项目旧服务，请先在原终端按 Ctrl+C。本地默认只监听本机；公网部署使用 Dockerfile，并设置 HTTPS 与持久化磁盘。

开发：`APP_ORIGIN=http://127.0.0.1:5173 npm run dev`，网页 <http://127.0.0.1:5173>，后端 3001，Vite 代理 `/api`。开发网页地址应与 `APP_ORIGIN` 一致，以通过来源校验。修改源码后，生产式预览需重新 `npm run build`；后端变更还需重启 `npm start`。

## 比赛当天操作

1. 管理员在“成员与权限”创建评委账号。管理员如也需评分，必须另行勾选评委角色。
2. 核对队伍和评委人数，在“赛事设置”开始评分。此时固定本场评委名单；开赛后新增账号不会自动进入本场。
3. 评委登录即进入评分页，通过滑块或数字输入给出 0—10 分、间隔 0.5 分的综合分。六维度只供判断参考，不再次加权。评语选填。
4. 只有服务器确认后才显示已提交，并进入下一支未评分队伍。0 分有效。草稿按账号和队伍保存在当前浏览器；断网后继续填写，联网后主动提交。跨浏览器的草稿不互通。
5. 截止前可更新本人评分；冲突时先核对最新记录。管理员只查看分数和改分记录，不能代评或改分。
6. 管理员结束评分。未收齐时仍明确标记“尚未收齐”；如需重新开放，必须填写原因，名单保持不变。可导出队伍汇总与逐评委 CSV。

均分按所有已提交的有效分数算术平均，显示两位小数；排名按未舍入结果计算，完全同分并列，名次采用 1、1、3。停用或移除角色不会删除已有成绩，缺评仍按固定名单统计。

管理员“成绩与进度”默认按排名展示，每 2 秒自动同步；管理员导航下的“实时榜单”提供白底、深色文字和浅金色强调的成绩卡片，并支持全屏展示，展示所有队伍均分、并列名次与收齐进度。未收齐或仍开放评分时标为“暂定排名”，全部评分收齐且结束评分后显示“最终成绩”。网络异常时保留上次数据并显示同步中断。

队伍汇总 CSV 按排名排序，包含均分、已评/应评人数、收齐状态、成绩状态和导出时间；逐评委 CSV 保留评分、评语和更新时间。所有评委等权，不去最高最低分。评委端优先展示独立的评分卡片与评语卡片，评分参考置于下方且默认收起；支持团队合照预览、0.5 分微调与轻量动效，遵循系统“减少动态效果”设置。

## 备份与恢复

服务运行时可执行一致性在线备份，不能直接只复制 `.sqlite` 文件而漏掉 WAL：

```sh
npm run db:backup
# 或指定一个尚不存在的备份路径
npm run db:backup -- ./data/backups/before-finals.sqlite
```

恢复前必须停止服务，并避免运行其他会写入同一数据库的命令：

```sh
npm run db:restore -- ./data/backups/before-finals.sqlite
npm start
```

恢复命令验证完整性与结构版本，先保存旧库为 `.before-restore-时间戳`，再替换；恢复后清除登录会话，需要重新登录。检测到运行中的服务 PID 会拒绝恢复。默认不覆盖备份。自定义数据库路径通过 `DB_PATH` 指定。

SQLite 使用 WAL、FULL 同步、事务、唯一键；锁定 `better-sqlite3@13.0.3`，本机实际 SQLite 3.53.4。启动检查最低 3.51.3，包含官方说明的 WAL 修复。数据应放在本机磁盘；交接后若需多实例或网络盘，请先调整数据层，勿把本地文件直接放共享盘。
